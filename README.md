# 🧠 How I Approach Data Problems

My preferred workflow is:

```text
          UNDERSTAND
              ↓
          INVESTIGATE
              ↓
            BUILD
              ↓
           VALIDATE
              ↓
           EXPLAIN
```

### 1. Understand

What is the actual business or operational question?

### 2. Investigate

What data exists?

What does each row represent?

How are the entities related?

Where could the data be incomplete, duplicated, malformed, or misleading?

### 3. Build

Translate the requirement into:

- SQL
- Python
- Regex
- Data transformations
- Validation rules

### 4. Validate

Ask:

- Are duplicates affecting the result?
- Did a join multiply rows?
- Are NULLs handled correctly?
- Are edge cases covered?
- Does the output actually answer the original question?
- Can I independently verify the result?

### 5. Explain

A technically correct solution is more valuable when the reasoning behind it can also be communicated clearly.
